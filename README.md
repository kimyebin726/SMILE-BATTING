# 미소배틀 (SMILE BATTING)

두 사람이 카메라 앞에 나란히 앉아, **먼저 웃음이 터진 쪽이 지는** 2인 대결 웹게임입니다.

▶️ **[플레이하기](https://kimyebin726.github.io/SMILE-BATTING/)**

세로 화면(460×940 기준)에 맞춰 설계되어 있어 모바일에서 가장 잘 동작합니다.

---

## 게임 흐름

| 화면 | 내용 |
|---|---|
| 타이틀 | `게임 시작` |
| 닉네임 | 선수 1·2 닉네임 입력 (각 2~10자, 랭킹에 반영) |
| 카메라 | 한 화면에 두 얼굴이 나오도록 카메라 켜기 |
| 카운트다운 | 3 → 2 → 1 |
| 대결 | 웃음 게이지가 좌우로 밀리는 실시간 줄다리기 |
| 결과 | 승리 / 패배 + 점수 |
| 랭킹 | 전체 랭킹에서 내 순위 확인 |

대결 중에는 `푸흡!` `참아!` `큭` `터졌다!` `흐흐` 같은 리액션이 양쪽에 무작위로 튀어나옵니다.

## 어떻게 판정하나요

카메라 영상을 **64×48 크기로 축소해 프레임 간 픽셀 변화량을 좌우 절반으로 나눠 비교**합니다. 화면 위쪽 35%는 제외하고 아래쪽만 보기 때문에, 주로 입·턱·어깨의 움직임이 반영됩니다.

- 움직임이 많은 쪽으로 게이지가 밀립니다 — 웃음을 참으면 유리합니다
- 게이지는 매 120ms 갱신되며, 튀지 않게 이전 값에 82% 가중치를 두고 부드럽게 이어집니다
- 게이지는 8~92% 범위로 제한되어 한쪽이 즉시 끝나지 않습니다
- 제한 시간이 끝난 순간 게이지가 **50% 이상이면 선수 1 승리**, 미만이면 선수 2 승리

> 얼굴 인식이나 표정 분석 AI를 쓰지 않습니다. 순수하게 움직임 변화량만 측정하므로, 웃지 않고 몸을 흔들어도 게이지가 움직입니다.

**카메라 없이도 플레이할 수 있습니다.** 카메라 켜기 버튼을 한 번 더 누르면 카메라 없이 진행되고, 이때 게이지는 무작위로 움직입니다.

## 설정값

| 항목 | 기본값 | 범위 |
|---|---|---|
| `roundSeconds` — 한 라운드 길이 | 30초 | 5~60초 (5초 단위) |
| `musicVolume` — 배경음 볼륨 | 0.6 | 0~1 |
| `gaugeStyle` — 게이지 모양 | `bar` | `bar` `blocks` `tug` `dots` `pixel` `dual` |

## 브라우저 요구사항

카메라 모드는 **HTTPS 환경에서만** 동작합니다 (`getUserMedia` 제약). 배포된 GitHub Pages 주소는 HTTPS이므로 그대로 쓰시면 됩니다.

최신 Chrome 또는 Safari를 권장합니다. 아래 상황은 게임 안에서 안내 메시지로 처리됩니다.

- 브라우저가 카메라를 지원하지 않음
- 카메라 권한 거부 → 주소창의 카메라 아이콘에서 허용으로 변경
- 카메라를 찾을 수 없음 → 다른 앱이 사용 중인지 확인

**영상은 기기 밖으로 나가지 않습니다.** 촬영된 프레임은 브라우저 안의 캔버스에서 움직임 계산에만 쓰이고, 어디에도 저장되거나 전송되지 않습니다.

## 알려진 제약

- **랭킹은 저장되지 않습니다.** 상위 3인(`루미` 98점, `모던이` 94점, `해피니` 91점)은 고정값이고, 내 점수를 그 사이에 끼워 순위를 보여주는 방식입니다. 새로고침하면 초기화됩니다.
- 첫 로딩에 약 21MB를 받습니다 (아래 참고).

## 저장소 구조

```
index.html    단일 파일 빌드 — 자산 49개가 모두 내장됨
.nojekyll     GitHub Pages의 Jekyll 처리 비활성화
README.md
```

`index.html` 하나가 게임 전체입니다. 별도 빌드나 서버 없이 파일을 브라우저로 열면 바로 실행됩니다 (단, 카메라는 HTTPS에서만 동작).

React 18.3.1을 포함한 모든 자산 — 이미지 29개, 오디오 1개, 웹폰트 15개(Barlow) — 이 `<script type="__bundler/manifest">` 블록 안에 base64로 들어 있고, 페이지 로드 시 Blob URL로 풀려 사용됩니다.

**크기**: 원본 30.0MB → gzip 전송 시 약 21MB. base64는 원본 바이너리보다 33% 커지는데, GitHub Pages의 gzip 압축이 그만큼을 되돌려 줍니다.

## 배포

`main` 브랜치 루트를 GitHub Pages가 그대로 서빙합니다. 새 빌드를 올리려면 `index.html`을 교체하고 push하면 됩니다.

```bash
cp "새 빌드.html" index.html
git add index.html && git commit -m "Update build" && git push
```

빌드마다 자산 UUID가 새로 생성되므로 diff는 항상 파일 전체로 잡힙니다.

> 참고: GitHub 웹사이트의 드래그&드롭 업로드는 파일당 25MB까지만 허용합니다. 이 파일은 그보다 크므로 **git CLI로 push해야 합니다** (git 제한은 100MB).
