# 미소배틀 (SMILE BATTING)

두 사람이 카메라 앞에 나란히 앉아, **먼저 웃음이 터진 쪽이 지는** 2인 대결 웹게임입니다.

▶️ **[플레이하기](https://kimyebin726.github.io/SMILE-BATTING/)**

세로 화면(460×940 기준)에 맞춰 설계되어 있어 모바일에서 가장 잘 동작합니다.

---

## 게임 흐름

| 화면 | 내용 |
|---|---|
| 타이틀 | `게임 시작` |
| 닉네임 | 선수 1·2 닉네임 입력 (각 2~10자, 랭킹에 반영) |
| 카메라 | 한 화면에 두 얼굴이 나오도록 카메라 켜기 |
| 카운트다운 | 3 → 2 → 1 (화면 정중앙) |
| 대결 | 웃음 게이지가 좌우로 밀리는 실시간 줄다리기 + 실시간 점수 |
| 결과 | 승리 / 패배 + 최종 점수 + 총 랭킹 |
| 랭킹 | 전체 랭킹 화면 (정적 이미지 — 아래 *알려진 제약* 참고) |

대결 중에는 `푸흡!` `참아!` `큭` `터졌다!` `흐흐` 같은 리액션이 양쪽에 무작위로 튀어나옵니다.

## 어떻게 판정하나요

카메라 영상을 **64×48 크기로 축소해 프레임 간 픽셀 변화량을 좌우 절반으로 나눠 비교**합니다. 화면 위쪽 35%는 제외하고 아래쪽만 보기 때문에, 주로 입·턱·어깨의 움직임이 반영됩니다.

- 움직임이 많은 쪽으로 게이지가 밀립니다 — 웃음을 참으면 유리합니다
- 게이지는 매 120ms 갱신되며, 튀지 않게 이전 값에 82% 가중치를 두고 부드럽게 이어집니다
- 게이지는 8~92% 범위로 제한되어 한쪽이 즉시 끝나지 않습니다
- 제한 시간이 끝난 순간 게이지가 **50% 이상이면 선수 1 승리**, 미만이면 선수 2 승리

> 얼굴 인식이나 표정 분석 AI를 쓰지 않습니다. 순수하게 움직임 변화량만 측정하므로, 웃지 않고 몸을 흔들어도 게이지가 움직입니다.

**카메라 없이도 플레이할 수 있습니다.** 카메라 켜기 버튼을 한 번 더 누르면 카메라 없이 진행되고, 이때 게이지는 무작위로 움직입니다.

## 점수

두 선수의 점수가 대결 중 **실시간으로 오릅니다.** 게이지 아래에 7자리 0-패딩(`0082788`)으로 표시되고, 매 120ms마다 갱신됩니다.

한 틱에 오르는 점수는 이렇게 정해집니다.

```
점수 = (1400 + 우세도² × 8000) × 연속배수 × 길이보정
```

| 항목 | 설명 |
|---|---|
| 우세도 | 게이지에서 앞선 정도 (0~1) |
| 연속배수 | 계속 앞서면 약 7초에 걸쳐 1.0 → 2.2배로 상승, 역전당하면 1.0으로 초기화 |
| 길이보정 | `30 / roundSeconds` — 라운드 길이가 달라도 점수 규모가 같게 유지 |

- **뒤진 쪽도 매 틱 1400점씩 오릅니다.** 숫자가 멈추지 않아서 양쪽 모두 올라가는 느낌을 받습니다. 격차는 우세도와 연속배수가 만듭니다.
- 상한은 `9999999`입니다. 30초 라운드에서 압도적으로 이겨도 약 445만 점이라 실제로는 닿지 않는 안전장치입니다.

30초 기준 실측 평균(각 200회 시뮬레이션):

| 대결 양상 | 최종 점수 | 총 랭킹 |
|---|---|---|
| 막상막하 | 약 37만 | 4위 |
| 약간 우세 | 약 108만 | 4위 |
| 우세 | 약 215만 | 3위 |
| 압도 | 약 445만 | 1위 |

`roundSeconds`를 60초로 바꿔도 점수 규모는 거의 같습니다 (길이보정 덕분에 편차 1.05배). 보정이 없으면 60초 라운드가 30초의 2.3배를 받아 고정 랭킹이 무의미해집니다.

## 설정값

| 항목 | 기본값 | 범위 |
|---|---|---|
| `roundSeconds` — 한 라운드 길이 | 30초 | 5~60초 (5초 단위) |
| `musicVolume` — 배경음 볼륨 | 0.6 | 0~1 |
| `gaugeStyle` — 게이지 모양 | `bar` | `bar` `blocks` `tug` `dots` `pixel` `dual` |

## 브라우저 요구사항

카메라 모드는 **HTTPS 환경에서만** 동작합니다 (`getUserMedia` 제약). 배포된 GitHub Pages 주소는 HTTPS이므로 그대로 쓰시면 됩니다.

최신 Chrome 또는 Safari를 권장합니다. 아래 상황은 게임 안에서 안내 메시지로 처리됩니다.

- 브라우저가 카메라를 지원하지 않음
- 카메라 권한 거부 → 주소창의 카메라 아이콘에서 허용으로 변경
- 카메라를 찾을 수 없음 → 다른 앱이 사용 중인지 확인

**영상은 기기 밖으로 나가지 않습니다.** 촬영된 프레임은 브라우저 안의 캔버스에서 움직임 계산에만 쓰이고, 어디에도 저장되거나 전송되지 않습니다. 카메라는 대결·카메라 화면에서만 켜지고, 결과·랭킹·타이틀 화면으로 넘어가는 순간 트랙을 정지시켜 촬영 표시등을 끕니다. `다시 도전`을 누르면 (권한이 이미 있으므로) 재요청 없이 조용히 다시 켜집니다.

## 알려진 제약

- **랭킹은 저장되지 않습니다.** 결과 화면의 `총 랭킹`에 나오는 상위 3인(`루미` 3,850,000 / `모던이` 2,450,000 / `해피니` 1,450,000)은 코드에 박힌 고정값이고, 내 점수를 그 사이에 끼워 순위를 계산합니다. 새로고침하면 초기화됩니다. 백엔드도 `localStorage`도 쓰지 않습니다.
- **`전체 랭킹` 화면은 통째로 정적 이미지입니다.** 그림에 `루미 98,500점`, `내 순위 128위 · 72,000점`, `랭킹은 매일 00:00에 업데이트돼요!`가 박혀 있고, 실제 점수와 무관하게 항상 같은 내용이 나옵니다. 결과 화면의 `총 랭킹`만 실제 점수를 반영합니다.
- **화면별로 점수 자릿수가 다릅니다.** 타이틀 아트의 HUD는 6자리(`000000`, `HI-SCORE 123456`), 전체 랭킹 이미지는 5자리(`98,500점`), 실제 동작하는 점수는 7자리입니다. 앞의 둘은 그림이라 코드로는 바꿀 수 없습니다.
- 첫 로딩에 약 21MB를 받습니다 (아래 참고).

## 저장소 구조

```
index.html    단일 파일 빌드 — 자산 49개가 모두 내장됨
og.png        공유 링크 미리보기 카드 (1200×630)
.nojekyll     GitHub Pages의 Jekyll 처리 비활성화
README.md
```

`og.png`가 별도 파일인 이유가 있습니다. 링크 미리보기를 만드는 크롤러(카카오톡·슬랙 등)는 **JavaScript를 실행하지 않습니다.** 게임 자산은 전부 JS가 풀어내는 base64 안에 있어서 크롤러 눈에는 보이지 않으므로, 미리보기용 이미지만 실제 파일로 꺼내 두고 `index.html` 바깥쪽 `<head>`의 `og:image`가 이 파일을 가리킵니다. 같은 이유로 `<title>`과 `og:*` 태그도 그 바깥쪽 `<head>`에 있습니다.

`index.html` 하나가 게임 전체입니다. 별도 빌드나 서버 없이 파일을 브라우저로 열면 바로 실행됩니다 (단, 카메라는 HTTPS에서만 동작).

React 18.3.1을 포함한 모든 자산 — 이미지 29개, 오디오 1개, 웹폰트 15개(Barlow) — 이 `<script type="__bundler/manifest">` 블록 안에 base64로 들어 있고, 페이지 로드 시 Blob URL로 풀려 사용됩니다.

**크기**: 원본 30.0MB → gzip 전송 시 약 22.6MB. base64는 원본 바이너리보다 33% 커지는데, GitHub Pages의 gzip 압축이 그만큼을 되돌려 줍니다. 다만 오디오(MP3)는 이미 압축된 포맷이라 gzip이 더 줄여주지 못합니다.

## 배포

`main` 브랜치 루트를 GitHub Pages가 그대로 서빙합니다. 새 빌드를 올리려면 `index.html`을 교체하고 push하면 됩니다.

```bash
cp "새 빌드.html" index.html
git add index.html && git commit -m "Update build" && git push
```

빌드마다 자산 UUID가 새로 생성되므로 diff는 항상 파일 전체로 잡힙니다.

> 참고: GitHub 웹사이트의 드래그&드롭 업로드는 파일당 25MB까지만 허용합니다. 이 파일은 그보다 크므로 **git CLI로 push해야 합니다** (git 제한은 100MB).
